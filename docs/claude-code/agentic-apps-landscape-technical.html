Agentic Systems: Builders, Architectures & the Research Frontier

A technical survey of who is building agentic software and how — runtimes, protocols, benchmarks, and in-flight research — with three deep dives and a comparison. Assumes familiarity with LLMs, tool-calling, and RL.

Compiled 2026-05-26. GitHub stars fetched live this week. Benchmark scores and private valuations move fast; confidence is flagged inline (H verified / M reputable secondary / L unverified). arXiv IDs verified against arxiv.org unless flagged.

TL;DR for engineers

The stack is consolidating into layers: (1) frontier models with native tool-use/computer-use + RLVR post-training; (2) agent runtimes/frameworks (LangGraph, OpenAI Agents SDK, MS Agent Framework, CrewAI, Pydantic AI…); (3) interop protocols — MCP (agent↔tools) + A2A (agent↔agent), with agentic-payment standards still fragmented; (4) products (coding agents, computer-use, vertical enterprise).

Key shifts since 2025: SWE-bench Verified is saturating (→ SWE-bench Pro, contamination-resistant); evals moving from one-shot to pass^k reliability (τ-bench); computer-use (OSWorld) and long-horizon autonomy remain the hard walls; RLVR is the dominant training recipe (with reward-hacking as the live failure mode); memory is moving from RAG-over-history to agent-managed self-editing memory (MemGPT/Letta, Mem0, A-MEM).

1 · Taxonomy & reference architecture

An "agentic" system = an LLM in a perceive→plan→act→observe loop with tools, memory, and some autonomy over control flow. Minimum viable agent: model + tool schema + loop + stop condition. Production systems add the layers below.

# Reference layering (bottom → top) [ Model ] frontier LLM w/ tool-use, reasoning/extended-thinking, computer-use [ Harness ] agent loop · context mgmt/compaction · planner · reflection · verifier [ Memory ] short-term (context) + long-term (vector/graph) + self-editing (MemGPT) [ Tools ] function-calling · code exec (E2B sandbox) · browser · file I/O · MCP servers [ Interop ] MCP (agent↔tools) · A2A (agent↔agent) · AGNTCY (discovery/infra) [ Orchestr. ] single-agent | orchestrator-worker | role-based multi-agent | swarm [ Eval/Obs ] traces · benchmarks · pass^k reliability · LangSmith/Logfire/OTel

Two orthogonal axes that matter most in practice: (a) autonomy granularity — atomic tools the model composes freely vs. hard-coded workflows (the "agent-native" vs. pipeline debate); (b) reliability surface — guarantees must live in tool/harness code, not prompts (prompts are suggestions). Token cost scales ~linearly with autonomy: Anthropic reports multi-agent orchestration at ~15× single-agent tokens. M

5 · Three deep dives

Cursor (Anysphere) — retrieval-first agentic IDE

closed-source · VS Code fork · ~$2B ARR · ~$29.3B¹

Technical thesis: the bottleneck for code agents is context selection, not raw model quality. Cursor's moat is a proprietary codebase indexing/retrieval ("context engine") + tight editor integration + background agents (async, parallel, cloud-executed tasks). Model-agnostic: routes across frontier models (Anthropic/OpenAI/its own fine-tunes) and applies edits via fast "apply" models.

  • Loop: retrieve relevant context → propose multi-file diff → user/agent applies → run/iterate. Agent mode plans across files; background agents run headless.
  • Why it won: latency + UX on a daily workflow; "Tab" completion + agent in one surface. Fastest-ever B2B $0→$2B ARR.
  • Risk: sits atop frontier-lab models that now ship their own agents (Claude Code, Codex) — margin/differentiation pressure.

Manus (Butterfly Effect / Monica) — general agent on a virtual computer

closed-source · China · ~$100M ARR in ~8mo · reported Meta acq. $2B+¹ L

Technical thesis: wrap frontier models (reportedly Claude + Qwen-class) in a persistent cloud VM with shell, browser, file system, and a planning/"todo" loop, then let the agent run long-horizon tasks asynchronously to a finished deliverable. Emphasizes transparent execution ("Manus's Computer" view) and a context-engineering approach to long trajectories (KV-cache-friendly prompts, file-system-as-memory, recitation of goals to combat drift).

  • Self-reported GAIA (Manus 1.5): ~86% L1 / ~70% L2 / ~58% L3 L — treat as marketing until third-party-verified.
  • Significance: productized the "do the whole job" long-horizon pattern; proof a breakout agent can ship from anywhere and scale in months.
  • Risk: generalist agents face reliability/cost vs. focused agents; the Meta acquisition price is press-reported, not confirmed.

Sierra (Bret Taylor) — outcome-priced enterprise CX agents

closed-source · ~$15B · ~$150M ARR · outcome-based pricing

Technical thesis: reliability + governance are the product, not the model. Sierra wraps models in a guardrailed, policy-constrained agent with deterministic tool integrations (CRM, order systems), supervisory checks, and per-customer evals. Co-developed τ-bench / τ²-bench (Sierra Research) to measure exactly the thing enterprises care about: multi-turn reliability and policy adherence under pass^k.

  • Pricing innovation: charges largely per resolved outcome — only viable because the agent does verifiable end-to-end work; aligns vendor incentive with task success.
  • Significance: sets the template for vertical agents (reliability eng + outcome pricing + domain integrations) and contributes real eval methodology back to the field.
  • Risk: outcome attribution/guarantees are hard; long enterprise sales cycles; incumbents (Salesforce Agentforce) competing.

7 · Interop & payment protocols

MCP — Model Context Protocol (Anthropic, community-governed)

JSON-RPC 2.0; roles Host / Client / Server; servers expose Resources, Prompts, Tools; clients expose Sampling, Roots, Elicitation. Stateful w/ capability negotiation (modeled on LSP). Ratified spec 2025-11-25 H. RC in progress: stateless core, Extensions, Tasks (async long-running), MCP Apps (UI), OAuth 2.1 auth hardening M. Public server registry growing; verified/security-rated registry on 2026 roadmap. De-facto "tool port" for agents (OpenAI/Google interop). spec

A2A — Agent2Agent (Google → Linux Foundation, Jun 2025)

Agent↔agent (peer), complementary to MCP. Primitives: Agent Cards (capability discovery), Tasks, transport over HTTP + SSE + JSON-RPC. Opaque-agent interop without exposing internal state. 100+ supporters; vendor-neutral under LF. H The emerging two-layer stack = MCP (tools) + A2A (agents). a2a-protocol.org

AGNTCY / "Internet of Agents" (Cisco + LangChain + Galileo → LF)

Broader infra stack: discovery, composition, deployment, eval; OASF agent manifest/directory. 65+ companies; LF governance. Overlaps/competes with A2A at the infra layer. agntcy.org

Agentic payments (fragmented — no winner)

Open problems: delegated authorization, scoped consent, agent identity/attestation, dispute/liability. Contenders: AP2 (Google, signed mandates/verifiable credentials, 60+ partners incl. Mastercard/PayPal/Coinbase), x402 (Coinbase, HTTP-402 stablecoin micropayments for M2M), Visa TAP (agent identity in HTTP headers), Mastercard Agent Pay (tokenized agentic credentials), ACP (OpenAI/Stripe in-ChatGPT checkout). All M/L on adoption specifics.

9 · Research frontier (incl. in-progress)

Memory

MemGPT/Letta (2310.08560) — "LLM as OS": virtual context mgmt, tiered memory, self-editing via function calls. Mem0 (2504.19413) — extraction→consolidation→retrieval; benchmarked on LoCoMo. A-MEM (2502.12110) — Zettelkasten-style interconnected evolving notes; gains on multi-hop. Direction: RAG-over-history → agent-managed self-evolving memory; eval still immature. H

Self-improvement / open-ended

Reflexion (2303.11366) — verbal RL: reflect on failures into episodic memory (no weight updates). Voyager (2305.16291) — open-ended Minecraft agent w/ automatic curriculum + executable skill library + self-verification; foundational for lifelong-learning/skill-library agents. H

RL for agents (RLVR, verifiers, test-time compute)

RLVR (RL w/ Verifiable Rewards) is the dominant post-training recipe — reward from programmatic checks (tests/math/format). Canonical: DeepSeek-R1 GRPO rule-based rewards; OpenAI o-series "scale RL + tool use." Live failure mode: reward hacking / verifier gaming. Unifying reasoners+verifiers for test-time scaling (2505.04842); contrarian result that RLVR sharpens sampling more than it adds capability (2506.14245). H on these IDs; 2026-dated IDs from search L — verify before citing.

Multi-agent orchestration & long-horizon

Anthropic multi-agent research system: orchestrator-worker; lead decomposes → parallel subagents (explicit objective/format/tools) → synthesize. +90.2% vs single-agent on internal evals at ~15× tokens; token usage explained ~80% of variance. Heuristics: 1 agent fact-find, 2–4 compare, 10+ complex. M Long-horizon autonomy (error compounding, credit assignment, trajectory repair) remains the central open problem.

Computer-use models & world models

Distinct model class: vision + GUI grounding + RL on UI (OpenAI CUA, Anthropic computer-use, Gemini computer-use). OSWorld is the proving ground; grounding is the bottleneck. World models for agents (Genie-line / learned simulators, DeepMind) — sample-efficient training/planning, research-stage.

Frontier products & autonomous science

OpenAI (ChatGPT agent absorbing Operator/CUA; o-series + GPT-5.x for agentic coding/computer-use), Anthropic (Claude Code + Agent SDK + MCP; computer-use), Google DeepMind (Project Mariner ~10 parallel tasks; Project Astra real-time multimodal assistant). Sakana "AI Scientist" v2 (2504.08066) — agentic tree-search research pipeline; produced the first AI-generated manuscript to pass workshop peer review at ICLR 2025 (avg 6.33) — heavily caveated: hallucinations/overstated novelty (critical eval 2502.14297). 10 · Open problems & what to watch

  • Long-horizon reliability — error compounds over long trajectories; credit assignment and mid-run trajectory repair are unsolved. The real moat is reliability eng, not model access.
  • Computer-use grounding — OSWorld shows GUI grounding + operational knowledge is far from solved; biggest near-term capability unlock.
  • Eval integrity — Verified saturation/contamination → Pro + pass^k + contamination-resistant suites. Don't trust single-number leaderboards; measure pass^k on your task.
  • RLVR reward hacking — verifier gaming is the dominant failure of the dominant training recipe; verifier design is becoming its own discipline.
  • Interop & identity — MCP+A2A converging fast; agent identity, scoped consent, and payments are the unsettled frontier (AP2/x402/TAP).
  • Cost of autonomy — multi-agent ~15× tokens; orchestration topology is a cost/quality dial, not a free lunch.
  • Memory — self-editing/evolving memory is promising but under-evaluated; LoCoMo-class benchmarks are early.
